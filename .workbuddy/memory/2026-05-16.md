## Agent 聊天隔离 bug 修复

### 问题
用户反馈 agent 聊天记录仍然跨用户共享（所有人聊天记录在一起的）

### 根因
1. `src/storage.py` 的 `get_chat_sessions` 方法中，`user_id` 条件和 `session_prefix`/`exact_ids` 条件用 `or_()` 连接，导致 user_id 过滤失效
2. 代码修复前产生的 8 条旧消息 `user_id` 为 NULL，`user_id == X` 不匹配 NULL 记录

### 修复
- `src/storage.py` — `get_chat_sessions`：
  - 将 `user_id` 从 `or_()` 条件中分离，作为独立的 AND 过滤条件
  - `session_prefix`/`exact_ids` 保留为 OR 条件（附加在 user_id 过滤之后）
  - 修复前：`WHERE (user_id=X OR session_id LIKE prefix% OR session_id IN (...))`
  - 修复后：`WHERE user_id=X AND (session_id LIKE prefix% OR session_id IN (...))`
- 旧数据回填：将 8 条 `user_id=NULL` 的 ConversationMessage 更新为 `user_id=1`（admin）

### 端到端验证
- admin 登录 → 4 个会话，testuser 登录 → 0 个会话
- testuser 用 admin 的 session_id 访问 → 0 条消息（跨用户访问被隔离）
- Session overlap = 0 ✅

## Agent 聊天前端隔离修复

### 问题
用户反馈 agent 聊天"还是没隔离"，后端存储层已隔离但前端仍显示旧用户数据

### 根因
1. 前端 `agentChatStore` 在用户切换时不会重置状态：`hasInitialLoad` 一旦为 true 就不再执行 `loadInitialSession`，导致切换用户后仍显示旧会话列表
2. `localStorage` 中的 `dsa_chat_session_id` 在登出时不清除，导致新用户可能复用旧 session_id
3. `AuthContext` 的 `logout`/`login` 流程不触发 chat store 重置

### 修复
- `apps/dsa-web/src/stores/agentChatStore.ts`：
  - 新增 `resetStore()` 方法：清除 sessions/messages/sessionId/hasInitialLoad，清除 localStorage 中的 session_id
- `apps/dsa-web/src/contexts/AuthContext.tsx`：
  - `fetchStatus` 中检测 currentUser.id 变化（用户切换）或登出时，自动调用 `useAgentChatStore.getState().resetStore()`
  - 网络错误时也调用 resetStore
- `src/agent/orchestrator.py`：
  - `chat()` 方法签名新增 `user_id: Optional[int] = None` 参数
  - 3处 `conversation_manager.add_message` 调用传入 user_id（修复 multi 模式下的隔离 bug）
- `api/v1/endpoints/agent.py`：删除重复的 `return response` 语句

### 验证
- 后端 API 层面：admin 3 个会话，tom 1 个会话，testuser 0 个会话，交叉访问返回空
- 前端构建通过
